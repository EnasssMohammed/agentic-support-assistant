# خريطة الكود: كل ملف، وغرضه، وعلاقته بالباقي

النسخة الإنجليزية: [04-code-map.en.md](04-code-map.en.md)

مرجع المنهج: الفصل 5 (البنية والحدود بين الطبقات) والفصل 14.3 (حدود المستودع).

## الفكرة الأساسية

**النموذج يقترح، والكود يقرر.** النموذج يقرأ الرسالة والسياسة ويقترح قراراً (أجب، شخّص، اسأل، صعّد).
الكود هو الذي يتحقق من القرار وينفذه، ويرفضه أو يعدّله إن خالف القواعد.

## رحلة رسالة واحدة

مثال: العميل يكتب "لا أستطيع تسجيل الدخول إلى حسابي".

```
ui/pages.py ──► src/agent_loop.py (الدماغ)
                 ├─ conversation.py     يحفظ الرسالة ويعرف المشكلة الحالية
                 ├─ intents.py          يصنّف الموضوع (حساب / راوتر / فواتير)
                 ├─ retrieval_agent.py ─► rag_engine.py    يجلب السياسة المناسبة للموضوع
                 │                      └► model_client.py  يسأل النموذج بشكل منظم (schemas.py)
                 ├─ قواعد الكود         ترفض قرار النموذج أو تعدّله
                 ├─ diagnostics.py      الأداة الوحيدة: فحص الراوتر
                 ├─ escalation.py       ينشئ ملف التذكرة ─► approval.py (طلب موافقة)
                 └─ responses.py        يصيغ الردود الثابتة بنبرة موحدة
```

ثم تعرض `ui/pages.py` الرد، وتظهر التذكرة في Team Inbox عبر `ui/tickets.py`.

## 1) قلب الوكيل: `src/`

| الملف | غرضه | علاقته |
|---|---|---|
| `agent_loop.py` | أهم ملف. يدير المحادثة: يتحقق من المدخل، يتتبع المشكلة، ويطبق القواعد: التصعيد بعد 3 محاولات، Hard Fault فوراً، التشخيص قبل الإرشاد، تشخيص واحد فقط | يستدعي كل الملفات أدناه |
| `conversation.py` | الذاكرة: الرسائل، نتيجة التشخيص، التذكرة، وموضوع المشكلة الحالية وبدايتها | يستخدمه `agent_loop` و`ui` |
| `schemas.py` | شكل قرار النموذج `AgentDecision` (الفعل، السبب، هل يصعّد، الرد). يجبر النموذج على JSON بدل نص حر | يستخدمه `model_client` و`retrieval_agent` |
| `intents.py` | قرارات حتمية بالكلمات: هل أكد العميل الحل؟ هل المشكلة ما زالت؟ ما موضوعها؟ ما الأدلة الناقصة؟ | يستخدمه `agent_loop` و`rag_engine` |
| `responses.py` | الردود الثابتة بالعربية (التصعيد، طلب التفاصيل، الحل) وتنسيق الخطوات | يستخدمه `agent_loop` |
| `retrieval_agent.py` | يبني الطلب للنموذج (السياسة + سجل المشكلة + الرسالة) ويحمل موجّه النظام وقواعده | يستدعي `rag_engine` و`model_client` |
| `rag_engine.py` | قاعدة المعرفة: تقسم `technical_docs.txt` بنداً بنداً، تحولها لتضمينات، وتبحث بحسب الموضوع | يقرأ `data/`، ويخزن في `chroma_langchain/` |
| `model_client.py` | حدّ النموذج: واجهة موحدة لـ OpenAI أو Ollama، مع `ModelClientError` | يستدعيه `retrieval_agent` |
| `settings.py` | يقرأ `.env` ويتحقق منه مرة واحدة (المزود، النموذج، المفتاح) | يستخدمه `model_client` و`rag_engine` |
| `diagnostics.py` | أداة الفحص الوهمية (سليم / عطل برمجي / عطل عتاد)، وقراءة ادعاءات العميل | يستدعيها `agent_loop` |
| `escalation.py` | ينشئ ملف التذكرة JSON: المشكلة، الأدلة، ما قيل للعميل، والخطوة التالية للموظف | يكتب في `tickets/` |
| `approval.py` | طلبات موافقة بشرية للإجراءات المحمية. يُنشأ الطلب لكن لا شيء يتوقف عليه بعد | يكتب في `approval_requests/` |
| `logging_config.py` | سجل الأحداث للشاشة ولملف `logs/velo.log` | يستخدمه الجميع |
| `baseline.py` | الوكيل البسيط (استدعاء واحد بلا أدوات). للمقارنة التاريخية فقط | المرحلة 1 |

## 2) الواجهات

| الملف | غرضه |
|---|---|
| `app.py` | المدخل: الشريط الجانبي والتنقل بين الصفحات |
| `ui/pages.py` | الصفحات: الرئيسية، Velo Agent (العميل)، Team Inbox (الفريق) |
| `ui/theme.py` | التصميم (CSS) والأيقونات |
| `ui/tickets.py` | يقرأ ملفات `tickets/` ويحفظ حالة كل تذكرة (جديدة، قيد المعالجة، مغلقة) |
| `main.py` | واجهة سطر الأوامر للتجربة السريعة |
| `.streamlit/config.toml` | ألوان Streamlit (اختياري) |

الوكيل يكتب التذكرة في `tickets/` والفريق يقرؤها من الملفات نفسها، فلا قاعدة بيانات بينهما.

## ثلاث قواعد تفسر معظم الكود

1. **الاعتماد في اتجاه واحد:** الواجهة ثم `agent_loop` ثم الأدوات والاسترجاع ثم حدّ النموذج.
   لا يستورد ملف سفلي ملفاً أعلى منه، فيسهل اختبار كل طبقة بمفردها.
2. **كل ضابط في الكود لا في الموجّه:** قاعدة مثل "شخّص أولاً" كانت في الموجّه فقط،
   وأثبت التقييم أن النموذج لا يلتزم بها دائماً، فنُقلت إلى `agent_loop`.
3. **كل ما قد يفشل له مسار آمن:** انقطاع النموذج أو الاسترجاع أو الأداة ينتهي برد صادق
   وتذكرة عند اللزوم، لا بانهيار.

## ترتيب القراءة المقترح (نحو ساعة)

1. `schemas.py` (دقيقتان): شكل القرار.
2. `conversation.py`: ما الذي يُحفظ.
3. `agent_loop.py`: ابدأ بـ `reply` ثم `_decide_loop`. هذا هو القلب.
4. `retrieval_agent.py`: موجّه النظام وكيف يُبنى الطلب.
5. `escalation.py` ثم `ui/tickets.py`: كيف تنتقل التذكرة للفريق.
6. `test_issue_tracking.py`: يشرح السلوك المقصود بأمثلة حية، وهو أفضل توثيق للقواعد.

| التغيير | حدّث أيضاً |
|---|---|
| قاعدة جديدة في `agent_loop` | اختبار في `test_issue_tracking.py` وحالة في `cases_v2.jsonl` |
| بند جديد في `technical_docs.txt` | `test_rag_splitting.py` (عدد البنود ووسم الموضوع) |
| كلمات موضوع جديدة في `intents.py` | `test_intents.py` |
| نص رد جديد في `responses.py` | الحالات التي تتحقق من عبارات الرد في `cases_v2.jsonl` |
| إصدار جديد | `CHANGELOG.md` ووسم Git |
